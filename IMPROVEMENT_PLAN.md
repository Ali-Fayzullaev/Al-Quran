## Фаза 0 — Критические баги (приоритет №1)

### Шаг 0.1 — Исправить сериализацию дат в `journeyStore.ts`
**Статус:** DONE
**Проблема:** `Date`-объекты (`lastAttemptedAt`, `firstCompletedAt`, `achievements[id].unlockedAt`) хранятся в zustand-состоянии и персистятся через дефолтный JSON storage. После `JSON.stringify` → `JSON.parse` они возвращаются как строки, а код продолжает вызывать `.getTime()` / `.toDateString()` на них — падение после релоада страницы.
**Файлы:** `lib/journeyStore.ts` (строки ~174-175, 325, persist-конфиг ~421-423), `lib/journeyTypes.ts`.
**Что сделать:**
1. Хранить даты как ISO-строки (`string`) в типах и во всём коде, конвертировать в `Date` только в момент использования — либо
2. Добавить кастомный `storage` с `serialize`/`deserialize`, который восстанавливает `Date` при чтении.
3. Добавить `migrate`/`version` в persist-конфиг, чтобы существующие у пользователей данные не крашили страницу при обновлении.
**Готово, когда:** после `localStorage.setItem` → релоад страницы → все даты в journey-состоянии остаются рабочими `Date`/ISO-строками, без `TypeError` в консоли.

## Как использовать этот документ

- Берите шаги по одному, отмечайте статус.
- Фаза 0 — то, что реально ломает приложение или искажает данные пользователя (стрики, деньги времени, крэши). Делать первой.
- Фаза 1 — не баги, а технический долг, который делает будущие правки Фазы 0 дороже с каждым релизом. Делать после/вместе с Фазой 0, чтобы не чинить одно и то же 4 раза.
- Фазы 2-3 — видимое пользователю качество и доступность, не блокируют корректность.
- Фаза 4 — по мере наличия времени.
